# 研究内容1阶段B：负荷条件价值函数与常规QNN试验

## 1. 阶段B目标

阶段B从阶段A固定负荷切片

\[
Q_{u_w}(x)
\]

扩展到显式包含负荷条件的价值函数

\[
Q(x,u),
\]

其中 `x` 是当前四比特、两时段的机组启停子空间，`u=(L_0,L_1)` 是两时段系统负荷。阶段B并行研究：

1. 可直接解释和后续可编译的低阶负荷条件代理；
2. 常规意义上的 data-reuploading expectation-value QNN 回归器；
3. 直接学习 `C(x,u) < tau` 的 threshold-conditioned QNN 软分类器；
4. 后续再研究表现较好的模型如何接入相干 oracle 与 Grover/BBHT。

阶段A代码、正式结果与结论保持冻结，阶段B输出统一使用 `stage2_` 前缀。

## 2. 第一版实现

新增：

- `qubit_value_function/load_scenarios.py`
  - 只缩放固定负荷，发电机与备用规则保持不变；
  - 负荷归一化器只使用训练负荷拟合，避免测试负荷泄漏。
- `qubit_value_function/load_conditioned_qnn.py`
  - 四量子位精确 NumPy statevector；
  - 二层数据重上传；
  - 非对易数据旋转、可训练 `RY/RZ` 与 CNOT 环；
  - 回归器读取全部15个非空 `Z` 字符串期望值，再接线性读出头；
  - 阈值分类器直接读取 qubit 0 的 `|1>` 概率。
- `experiments/stage2_case14_load_qnn_pilot_cli.py`
  - 生成负荷条件ED/LP真值；
  - 比较二次岭回归与常规QNN回归；
  - 训练阈值条件QNN并报告不同概率截断下的precision/recall。
- `tests/test_load_conditioned_qnn.py`
  - 负荷缩放、归一化、期望值范围、回归训练与分类训练的独立回归测试。

当前QNN是离线精确statevector诊断模型，不是Aer MPS、量子硬件或已接入Grover的相干oracle。

## 3. 第一轮pilot协议

固定设置：

- 数据：`case14`；
- 时间窗口：`window_start=0`，两时段；
- 搜索子空间：发电机索引 `(0,5)`，四比特、16状态；
- 负荷倍率：`0.85, 0.925, 1.0, 1.075, 1.15`；
- 训练负荷：`0.85, 1.0, 1.15`；
- 未见负荷：`0.925, 1.075`；
- 训练状态：固定随机种子1选出的8个状态；
- 回归训练样本：3个训练负荷 × 8个训练状态 = 24；
- 真值审计：5个负荷 × 16状态 = 80次ED/LP。

回归评估分为：

- `train`：见过的负荷和状态；
- `seen_load_unseen_state`：见过的负荷、未见状态；
- `unseen_load_all_state`：未见负荷、全部状态；
- `unseen_load_unseen_state`：未见负荷、未见状态。

阈值QNN使用训练负荷中四个成本分位阈值构造训练标签，并在未见负荷上使用“8个训练状态中的真实最优成本”作为测试阈值。测试只统计8个未见状态。

## 5. 第一轮结论

第一轮结果不支持“直接把当前常规QNN替换阶段A相位代理”。QNN在训练集上的误差明显更低，但对未见状态和未见负荷的泛化反而弱于低阶岭回归，呈现明显过拟合。阈值QNN能够在较低截断下提高召回率，但假阳性较多，会增加ED/LP验证成本。

当前可支持的结论是：

1. 负荷输入与常规QNN训练链路已经跑通；
2. “更常规的QNN”不自动带来更好的训练集外价值函数；
3. 直接学习阈值谓词具有召回潜力，但尚未达到精确joint oracle所需的候选质量；
4. 暂时不应替换阶段A已验证的相位值寄存器和严格比较器。

这只是单一机组对、单一窗口、单一划分和有限迭代的诊断pilot，不构成模型优劣的正式结论。

## 6. 下一步实验顺序

1. 对QNN层数、读出集合、正则化、初始化和训练迭代进行只基于训练/验证集的系统选择；
2. 加入经典MLP、随机量子特征和简化读出QNN，判断性能来自量子线路还是高维读出头；
3. 扩展到多个机组对、三个时间窗口和多个状态划分；
4. 分开报告负荷插值、负荷外推、状态泛化及二者联合泛化；
5. 阈值QNN使用类别权重或margin损失，分别研究高precision和高recall工作点；
6. 只有当软分类器候选质量稳定后，再构造保持 `x` 寄存器不变的相干flag线路并接入振幅放大；
7. 同时继续发展可编译的负荷条件相位代理，作为精确Boolean oracle主线。
